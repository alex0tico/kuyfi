    [ VECTORS · CATALOG ]

    Attack vectors reference

    Page options
    View as Markdown Agent setup

    Complete catalog of Chaos Monkey vector families, names, and targeting rules — matched to the v0.1.0 source.

    On this page

    1. Math / boundary
    2. Authorization
    3. Call ordering
    4. Fee / BPS
    5. Liquidity
    6. Admin name patterns
    How to read this

    Every vector is simulated first. Names likeamount::MAX_I128 mean parameter amount received attackMAX_I128 while other params stayed at type-correct baselines. Deep narrative:Chaos Monkey.

    1 · Math / boundary

    Module fuzzer_math.ts + type_gen.ts — every function with parameters. One-variable-at-a-time. expectedToFail = false.

    TypeAttack labels
    Signed integersZERO ONE NEG_ONE MAX_*MIN_* (e.g. MAX_I128)
    Unsigned integersZERO ONE MAX_* — noNEG_ONE / MIN_*
    AddressRANDOM_ADDR_A RANDOM_ADDR_B
    BoolTRUE FALSE
    Bytes / BytesNEMPTY_BYTES ZERO_BYTES_N FF_BYTES_NLARGE_BYTES (256)
    StringEMPTY_STR LONG_STR (256)
    SymbolEMPTY_SYMBOL LONG_SYMBOL (32)OVERSIZE_SYMBOL (64)
    Vec<T>EMPTY_VEC ONE_ELEM_VEC TWO_ELEM_VEC
    Option<T>NONE SOME_BASELINE
    Timepoint / DurationZERO_TS MAX_TS ZERO_DUR MAX_DUR
    UDTsRecursive: one struct field / enum case / union payload slot at a time.MAX_UDT_DEPTH = 4; cycles / unresolved → skip (never invent).

    Zero-param functions get no math vectors.

    2 · Authorization / access control

    Module fuzzer_access.ts. Only this family setsexpectedToFail = true (math / fee / liquidity / call-order stayfalse).

    VectorTargetsBehavior
    UNAUTHORIZED_CALLAdmin-pattern names (substring)Call from ephemeral (non-admin) key with baseline args
    REINIT_ATTACKinitialize / init / setupRe-run initializer on already-deployed contract
    SELF_CALL_ATTACKExact name match only:set_admin | set_pending_admin |transfer_adminAttacker address in every Address param
    UNAUTHORIZED_ADDR_CALLNon-admin fn with Address paramUnrelated address in that slot; signed only by ephemeral key

    These are expected to fail. Success → oftenPOTENTIAL_VULN (still a hypothesis under black-box limits).

    SELF_CALL matching

    Unlike admin-pattern detection (substring includes),SELF_CALL_ATTACK uses exact equality on the function name. A name like try_set_admin is admin-shaped forUNAUTHORIZED_CALL but does not getSELF_CALL_ATTACK.

    3 · Call ordering

    Module fuzzer_call_order.ts — once per session (after per-function families). Same function twice with baselines. Rules:

    • ≤ 1 function per sequence group
    • A function is never reused across groups
    • Name match is substring on the lowercased function name
    • expectedToFail = false
    GroupName patterns
    REINIT_SEQUENCEinitialize, init, setup
    REPEATED_WITHDRAW_SEQUENCEwithdraw, remove
    REPEATED_CLAIM_SEQUENCEclaim only (no harvest pattern in v0.1.0)

    4 · Fee / BPS

    Module fuzzer_fee.ts — numeric params whose names match/fee|fees|bps|basis_point/i and whose type is u32 / i32 / u64 / i64 / u128 / i128.

    Labels: BPS_0, BPS_1, BPS_9999,BPS_10000, BPS_10001, plus MAX_<TYPE>(e.g. type max — not a generic “type max” string). Rejecting 10001 is expected for well-guarded fee setters; this family checks boundaries are handled, not that rejection is a bug. expectedToFail = false.

    5 · Liquidity ratio

    Module fuzzer_liquidity.ts — functions matching/liquidity|swap|reserve/i with at least two numeric params. Attacks thefirst two numeric params by position as a pair; others stay at baseline.

    Exact pair labels:

    • ZERO_A_MAX_B, MAX_A_ZERO_B
    • MAX_A_MAX_B
    • ONE_A_MAX_B, MAX_A_ONE_B
    • MIN_A_MAX_B — only when param A is signed

    Vector name shape:LIQUIDITY::<paramA>x<paramB>::<pairLabel>.expectedToFail = false.

    Admin name patterns

    pause, unpause, initialize, init, setup, upgrade,
set_admin, set_pending_admin, transfer_admin, emergency

    Matching for admin detection is substring on the lowercased function name (isAdminFunctionByName). Self-call uses the exact-match list above.
