    [ 03 · PIPELINE ]

    From Contract ID to execution evidence.

    The OSINT Scanner maps functions, arguments and user-defined types first. Chaos Monkey then generates type-aware inputs, simulates execution and classifies the resulting traces. When an execution reaches the network, Kuyfi preserves the available transaction evidence alongside the report.

    1. 01INPUTContract ID
    2. 02OSINT SCANNERFetch deployed WASM / specification
    3. 03RECONSTRUCTReconstruct attack surface
    4. 04CHAOS MONKEYGenerate type-aware vectors
    5. 05SIMULATESimulate and classify
    6. 06OUTPUTJSON / PDF report

    Step by step

    01 · INPUT — Contract ID

    You provide a Soroban Contract ID (C + 55 characters). Validation is shared between TUI and CLI via isValidContractId(). A malformed ID fails before any RPC work (and before any paid quote on the HTTP API).

    02 · OSINT SCANNER — Fetch WASM / specification

    Read-only RPC: getContractWasmByContractId. No transactions are broadcast. The scanner compiles the bytecode, reads the contractspecv0 custom section, and parses XDR entries with an alignment-tolerant loop.

    03 · RECONSTRUCT — Attack surface

    Output: function names, typed parameters, return presence, and a UDT registry (structs / unions / enums). This is everything Chaos Monkey needs to generate type-correct values — still without Rust source.

    04 · CHAOS MONKEY — Type-aware vectors

    Five vector families (math, access-control, call-order, fee/BPS, liquidity). Values aretype-correct, not semantically valid: a random Address is not a funded admin. Attacks vary one variable at a time so failures can be attributed.

    05 · SIMULATE — Simulate and classify

    Every vector is simulated (preflight) first. If simulation fails, Kuyfi classifies fromDiagnosticEvent traces and sends nothing. If it succeeds, assemble → sign with an ephemeral Friendbot key → broadcast to Testnet → poll → classify.

    06 · OUTPUT — JSON / PDF report

    One SecurityReport (schemaVersion: "1.0.0"). JSON and PDF are renders of the same object — same reportId, findings, and evidence.

    UI ≠ engine

    TUI screens only call into source/modules/. The headless CLI uses the identical scanner / chaos_monkey / security_report / report_export path — zero duplication of audit logic.
