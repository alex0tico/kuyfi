    Interactive TUI

    Page options
    View as Markdown Agent setup

    Ink + React terminal UI — chrome only; all scanning and fuzzing live in source/modules/.

    On this page

    1. Menu modules
    2. Scan gate
    3. Layout tiers
    4. System Logs
    5. Exports

    Menu modules

    KeyModuleRole
    [1]OSINT ScannerMap attack surface → stores lastScanResult
    [2]Chaos MonkeyFuzz & stress test (requires prior scan)
    [3]System LogsStatic session status (not a live log stream)
    [4]AboutProject info

    Navigate with arrows or number keys; Enter to open; Esc to go back (ViewShell). Quit from the app → process.exit(0).

    Scan gate for Chaos Monkey

    app.tsx keeps lastScanResult / contractId in state. Opening Chaos Monkey when lastScanResult === null shows a notice (Run OSINT Scanner first…) instead of crashing — Chaos Monkey needs the reconstructed attack surface from a completed scan in this session.

    Headless vs TUI

    Headless kuyfi <CONTRACT_ID> always runs scan → Chaos Monkey in one shot. The TUI separates them so you can inspect the surface before fuzzing.

    Layout tiers

    • large — ≥ 100 columns
    • compact — 70–99 columns
    • tooSmall — < 70 cols or < 20 rows → TooSmallNotice

    useTerminalSize mitigates Ink shrink-resize artifacts (stale frames) with a debounced full-screen clear / ResizingNotice — without unmounting an in-flight scan or Chaos Monkey run.

    System Logs (static)

    LogsScreen is a static status panel: hardcoded Testnet RPC URL and session readiness strings. It is not a live RPC log stream and does not diagnose live connectivity failures. For per-contract pulls, use OSINT Scanner.

    Chaos Monkey exports

    After a campaign: [J] JSON · [P] PDF · [B] both → exportSecurityReport() with the same wx anti-overwrite policy as the CLI. Formats are attempted independently. Details →Reports.
